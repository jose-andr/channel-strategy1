## Current sprint focus

This sprint will run a lightweight off-platform search baseline alongside Intelligent Front Door Define.

The intent is not to complete the full Off-Platform Search discovery in one sprint.

The immediate focus is to:

- use the same priority customer journeys being explored through Intelligent Front Door Define where practical;
- turn those journeys and their customer reasons into realistic search queries and AI prompts;
- refine the test approach with relevant search / analytics input;
- run an initial current-state baseline across Google and at least one AI tool;
- assess accuracy, currency, source quality, actionability and customer usefulness;
- identify obvious source, routing or information-quality issues; and
- identify findings that may influence Intelligent Front Door or Information Architecture work.

Current candidate journeys include:

- residential parking applications;
- infringement review;
- payments;
- rates; and
- another journey only if evidence and sprint capacity justify it.

The test set should remain deliberately small enough to generate useful evidence rather than attempting a comprehensive search audit.

## Baseline assessment approach

For each tested query or prompt, record:

| Dimension | Assessment question |
| --- | --- |
| Customer intent | What is the customer trying to achieve? |
| Result | What answer, result or pathway is surfaced? |
| Accuracy | Is the information materially correct when checked against the authoritative City of Melbourne source? |
| Currency | Does the information appear current? |
| Source | What source or source type appears to underpin the result, where this can be identified? |
| Pathway | Does the result guide the customer toward the appropriate next step? |
| Consistency | Is the result broadly consistent with authoritative City of Melbourne information? |
| Customer usefulness | Would the result help the customer understand what to do next? |
| Issue | Is there inaccurate, outdated, incomplete, conflicting or poorly routed information? |
| Confidence | How confident are we in the finding given source visibility and result variability? |

Do not infer source provenance where it cannot be established.

## Evidence status

Use simple evidence labels for the baseline.

| Status | Meaning |
| --- | --- |
| Accurate | Materially consistent with the authoritative City of Melbourne source |
| Partially accurate | Broadly correct but incomplete, unclear or missing important context |
| Inaccurate | Materially incorrect or potentially misleading |
| Unclear | Insufficient evidence to determine accuracy |
| Source not identified | The underlying source cannot be determined reliably |

These labels describe the observed test result only.

They should not be treated as a definitive assessment of the search platform or AI tool as a whole.

## Connection to Intelligent Front Door Define

The current Off-Platform Search activity should support, but not duplicate, Intelligent Front Door Define.

Use the baseline to identify whether off-platform discovery contributes evidence about:

- how customers interpret the service before reaching an owned channel;
- whether customers are directed toward the correct pathway;
- whether information gaps may contribute to avoidable contact;
- whether external results create expectations that conflict with the owned-channel experience;
- whether source-of-truth issues affect the front-door experience; and
- whether Information Architecture improvements could strengthen both owned and off-platform discovery.

Relevant findings can inform Intelligent Front Door opportunity statements.

Detailed Off-Platform Search evidence and analysis should remain in this workstream.

## Current sprint completion check

The current sprint activity is complete enough when:

- a manageable set of priority journeys has been selected for testing;
- realistic customer queries / prompts have been documented;
- the test approach has been reviewed and refined with relevant search / analytics input;
- Google has been tested for the selected queries;
- at least one AI tool has been tested for the same or similar customer intents;
- accuracy, currency, source indications, pathway quality and customer usefulness have been recorded;
- material gaps or inconsistencies have been captured;
- evidence limitations and variable results are explicit;
- relevant implications for Intelligent Front Door or Information Architecture are identified; and
- the team can decide what Off-Platform Search discovery is worth doing next.

This sprint does **not** need to complete the full Discovery exit criteria unless the evidence genuinely supports doing so.
